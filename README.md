# Портрет технологического суверенитета · ТРИЗН–2026

Рабочий дашборд круглого стола «Технологический суверенитет: теории и практики». Три аспекта — оборудование; ПО, данные и вычисления; кадры и образование — связаны блоком государства и регуляторов.

- Помощник входит по коду и записывает статусы, формулировки, узкие места и решения.
- Зрители открывают `/` без входа; изменения появляются автоматически.
- Резолюция собирается по схеме «что — кто — к какому сроку». Итоги скачиваются.
- Общая карта хранится в SQLite на сервере и переживает перезапуск. При одновременных правках проверяется версия.
- Нет зависимости от ChatGPT, OpenAI, Cloudflare, внешних шрифтов или CDN при работе дашборда.

## Где работает сайт

GitHub хранит и проверяет проект. GitHub Pages не запускает серверную часть: для входа по коду и синхронизации разных компьютеров этот проект запускается на Node.js 24 либо в Docker.

Для доступа через интернет без зависимости от иностранного облака разверните проект на сервере в России. Доступность конкретного адреса проверяется с сети площадки перед круглым столом.

Для двух компьютеров в одном зале можно запустить приложение на одном из них и открыть его адрес с другого по общей локальной сети. VPN и интернет для работы в такой сети не требуются. Компьютер, на котором работает приложение, должен оставаться включённым.

## Локальный запуск

Нужен [Node.js 24](https://nodejs.org/en/download).

```sh
npm ci
npm run build
npm start
```

Экран зала: `http://localhost:8787/`. Заполнение: `http://localhost:8787/edit`.

В macOS можно открыть `Запустить.command`, в Windows — `Запустить.cmd`. Адреса для помощника и зрителей появятся в открывшемся окне. Компьютеры должны находиться в одной локальной сети; гостевая Wi-Fi-сеть может запрещать подключения между устройствами. Оставьте окно запуска открытым на время круглого стола.

Организатору также подготовлен архив `output/Круглый_стол_без_VPN.zip` со сборкой и текущим портретом. Распакуйте его целиком и откройте файл запуска. На компьютере, который запускает дашборд, нужен Node.js 24; помощнику и зрителям достаточно обычного браузера. Архив работает без загрузки библиотек из интернета. При первом запуске текущий портрет переносится в пустую базу; повторный запуск сохраняет новые записи.

При первом запуске генерируется случайный код. Он находится в `data/код-помощника.txt` и не попадает в Git. Передайте его только помощнику. Можно заранее установить свой код длиной не менее 12 символов через переменную `EDITOR_CODE`.

## Размещение на сервере

Достаточно одного небольшого сервера с Docker и домена, направленного на его IP. У сервера должны быть открыты порты 80 и 443. Создайте `.env` на сервере:

```dotenv
DASHBOARD_DOMAIN=your-dashboard.example.ru
EDITOR_CODE=replace-with-a-long-random-code
```

```sh
git clone https://github.com/JmsDiG/trizn-2026-sovereignty-dashboard.git
cd trizn-2026-sovereignty-dashboard
docker compose up -d --build
```

Caddy получает HTTPS-сертификат и передаёт запросы приложению. Записи остаются в отдельном постоянном томе `portrait-data` при обновлении контейнера. Сделайте резервную копию тома перед переносом сервера.

Чтобы обновить после изменения проекта в Git:

```sh
git pull --ff-only
docker compose up -d --build
```

Технические проверки запускаются в GitHub Actions. Это проверка проекта, а не размещение работающего сервера.

## Перенос данных из прежнего сайта

Прежняя версия на `chatgpt.site` продолжает существовать отдельно. В рабочей папке организатора сохранён экспорт `output/Портрет_для_переноса.json`. Он не публикуется в Git. Чтобы перенести его в новую пустую базу:

```sh
node server/import-portrait.mjs /path/to/Портрет_для_переноса.json
```

Импорт остановится, если в новой базе уже есть карта, и не изменит прежний сайт. Перед переносом проверьте актуальность экспорта.
